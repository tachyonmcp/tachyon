# 🌱 Spring Boot starter

Build → register annotated singletons → start transport. Native annotation contracts live in [[declarative-configuration]].

- `tachyon.*` → `TachyonProperties` record: flat `enabled=true`, `name`, `version`, `host`, `port=8080` plus nested `network`/`session`/`runtime` groups mirroring the `ServerBuilder` scopes ([TachyonProperties](../../integrations/tachyon-spring-boot-starter/src/main/java/dev/tachyonmcp/spring/boot/TachyonProperties.java)). One applier owns every builder call, driven by Boot's `PropertyMapper`: `PropertyMapper.get()` skips `null` sources by default (Boot 4 dropped `Source#whenNonNull`; `always()` opts out), so unset keys keep the core record's default ([TachyonPropertiesApplier#apply](../../integrations/tachyon-spring-boot-starter/src/main/java/dev/tachyonmcp/spring/boot/TachyonPropertiesApplier.java)). `List` → varargs goes through `StringUtils#toStringArray`. Values only — stores, generators, clocks and codecs stay `TachyonServerCustomizer` territory.
- Every `Duration` component carries `@DurationUnit(ChronoUnit.SECONDS)`. Boot's default unit for a suffixless `Duration` is **milliseconds**, so without it `reader-idle-timeout: 90` meant 90ms — three orders of magnitude off, and contradicting the "seconds will be used" the `@param` text promises and `TachyonConfigurationMetadataTest` enforces. An explicit suffix still wins ([TachyonPropertiesBindingTest#suffixlessDurationsBindAsSecondsAcrossEveryGroup](../../integrations/tachyon-spring-boot-starter/src/test/java/dev/tachyonmcp/spring/boot/TachyonPropertiesBindingTest.java)).
- A `tachyon.*` value the core builders would reject is rejected first as Boot's `InvalidConfigurationPropertyValueException`, so its built-in analyzer names the key and the file/line instead of the core's Java-API wording ([TachyonPropertiesApplier#rejectSessionOptions](../../integrations/tachyon-spring-boot-starter/src/main/java/dev/tachyonmcp/spring/boot/TachyonPropertiesApplier.java), [TachyonPropertiesApplier#toIntBytes](../../integrations/tachyon-spring-boot-starter/src/main/java/dev/tachyonmcp/spring/boot/TachyonPropertiesApplier.java)). Three cases: `session.enabled=false` beside a session option (mirrors `SessionConfig#SESSION_OPTIONS_REQUIRE_ENABLED` — never silently dropped), a `network.max-content-length` outside positive-`int` bytes or a `network.max-pending-sse-bytes` outside non-negative-`int` bytes, and a negative `network.max-pipelined-requests` ([TachyonPropertiesApplier#toNonNegativeRequests](../../integrations/tachyon-spring-boot-starter/src/main/java/dev/tachyonmcp/spring/boot/TachyonPropertiesApplier.java)). The analyzer needs no registration; Boot lists it in its own `spring.factories`.
- Config metadata: `@param` javadoc → `spring-configuration-metadata.json` via `spring-boot-configuration-processor`; documented defaults and value hints come from [additional-spring-configuration-metadata.json](../../integrations/tachyon-spring-boot-starter/src/main/resources/META-INF/additional-spring-configuration-metadata.json). `spring-boot-autoconfigure-processor` emits `spring-autoconfigure-metadata.properties` for condition pre-filtering. Both processors fail silently, so [TachyonConfigurationMetadataTest](../../integrations/tachyon-spring-boot-starter/src/test/java/dev/tachyonmcp/spring/boot/TachyonConfigurationMetadataTest.java) gates presence, Boot's description conventions, and drift of each documented default against the constant it copies.
- Builds server with properties, ordered extensions and customizers, then registers annotated beans after singleton initialization, before lifecycle startup ([ServerConfiguration#tachyonServer](../../integrations/tachyon-spring-boot-starter/src/main/java/dev/tachyonmcp/spring/boot/TachyonAutoConfiguration.java), [TachyonFeatureRegistrar#afterSingletonsInstantiated](../../integrations/tachyon-spring-boot-starter/src/main/java/dev/tachyonmcp/spring/boot/TachyonFeatureRegistrar.java)). Annotated beans can inject `TachyonServer`.
- Discovery uses `AopProxyUtils.ultimateTargetClass` on initialized beans; JDK and class proxies retain advice. Unrelated lazy beans stay uninitialized; lazy annotated beans need discoverable declared types ([TachyonFeatureRegistrar#afterSingletonsInstantiated](../../integrations/tachyon-spring-boot-starter/src/main/java/dev/tachyonmcp/spring/boot/TachyonFeatureRegistrar.java)).
- User server ⇒ construction and registrar back off together; lifecycle still supplied ([TachyonAutoConfiguration#TachyonAutoConfiguration](../../integrations/tachyon-spring-boot-starter/src/main/java/dev/tachyonmcp/spring/boot/TachyonAutoConfiguration.java), [ServerConfiguration](../../integrations/tachyon-spring-boot-starter/src/main/java/dev/tachyonmcp/spring/boot/TachyonAutoConfiguration.java)).
- Wire regression tests cover all three feature kinds through JDK proxy advice, server injection, custom codecs, lazy-bean isolation and user-server backoff ([TachyonBeanRegistrationTest#jdkProxyUsesTargetAnnotationsAndPreservesAdviceForEveryFeature](../../integrations/tachyon-spring-boot-starter/src/test/java/dev/tachyonmcp/spring/boot/TachyonBeanRegistrationTest.java)).
- Spring Boot `4.1.1` pinned in the root [pom.xml](../../pom.xml); the [module POM](../../integrations/tachyon-spring-boot-starter/pom.xml) imports `spring-boot-dependencies` at that version and depends on `spring-boot-starter`, which Boot requires every starter to pull in directly or indirectly. `spring-boot-health` and `micrometer-core` stay `<optional>`.
- `tachyon.enabled` gates the auto-configuration through `@ConditionalOnBooleanProperty(matchIfMissing = true)` ([TachyonAutoConfiguration](../../integrations/tachyon-spring-boot-starter/src/main/java/dev/tachyonmcp/spring/boot/TachyonAutoConfiguration.java)).
- 🔴 Don't flatten the nested configurations. Members inherit the outer `@ConditionalOnBooleanProperty` and the `afterName` ordering `@ConditionalOnBean(MeterRegistry.class)` needs; `TachyonAotProcessor#isInfrastructure` matches the `TachyonAutoConfiguration$` prefix, so a promoted `ServerConfiguration` warns on interface-typed `tachyonServer` ([TachyonAotProcessorTest#doesNotReportItsOwnOrSpringsInfrastructureBeans](../../integrations/tachyon-spring-boot-starter/src/test/java/dev/tachyonmcp/spring/boot/TachyonAotProcessorTest.java)).

- Completion-only beans retain target parameter names and proxy advice ([TachyonCompletionBeanTest#discoversCompletionOnlyProxyAndBindsTargetParameterNamesThroughAdvice](../../integrations/tachyon-spring-boot-starter/src/test/java/dev/tachyonmcp/spring/boot/TachyonCompletionBeanTest.java)).
- `TachyonServerLifecycle` starts/closes the server with the application context; lock serializes calls, `running` flips only after `start`/`close` succeeds (failure keeps prior state, retry allowed) ([TachyonServerLifecycle#start](../../integrations/tachyon-spring-boot-starter/src/main/java/dev/tachyonmcp/spring/boot/TachyonServerLifecycle.java)). Phase is stated, not defaulted: `TachyonServerLifecycle#PHASE` = `SmartLifecycle.DEFAULT_PHASE`, the highest there is, so MCP binds last and stops first — Spring's web server sits at `DEFAULT_PHASE - 2048`, its graceful shutdown at `- 1024`.
- 🔴 `TachyonServerLifecycle#isPauseable` returns `false`, overriding Spring 7's `true` default. `TachyonServer#close` is terminal and `start()` after it throws, so the stop/start cycle `ConfigurableApplicationContext#pause`/`restart` and CRaC checkpoint-restore apply to pauseable beans would strand the transport down. Boot's own `WebServerGracefulShutdownLifecycle` opts out the same way ([TachyonServerLifecycleTest#theTransportOptsOutOfContextPause](../../integrations/tachyon-spring-boot-starter/src/test/java/dev/tachyonmcp/spring/boot/TachyonServerLifecycleTest.java)).
- `TachyonServer` is `AutoCloseable` with an idempotent `close()`, so Spring's inferred destroy method closes it even when a user replaces the lifecycle bean, and the post-lifecycle second close is a no-op. Don't add `@Bean(destroyMethod = "")`.
- Actuator (all optional): `HealthConfiguration` carries `@ConditionalOnClass(HealthIndicator.class)` and `@ConditionalOnEnabledHealthIndicator("tachyon")` on one class (Boot's own `DiskSpaceHealthContributorAutoConfiguration` shape; condition attributes are read from ASM metadata, so a class literal is safe on an optional dependency) ⇒ `tachyon` indicator, `UP` + host/port iff lifecycle running, else `DOWN` + `state` = `not-started`/`stopped` from `TachyonServerLifecycle#hasStarted` (`port()` throws before bind, so the reads stay in the `UP` branch). Extends `AbstractHealthIndicator`, so anything that escapes the check becomes `DOWN` + `error` rather than a 500 out of the health endpoint ([TachyonHealthIndicator#doHealthCheck](../../integrations/tachyon-spring-boot-starter/src/main/java/dev/tachyonmcp/spring/boot/TachyonHealthIndicator.java), [TachyonActuatorAutoConfigurationTest#healthReportsDownInsteadOfThrowingWhenTheBindingCannotBeRead](../../integrations/tachyon-spring-boot-starter/src/test/java/dev/tachyonmcp/spring/boot/TachyonActuatorAutoConfigurationTest.java)). `MetricsConfiguration` carries `@ConditionalOnClass(MeterRegistry.class)` + `@ConditionalOnBean(MeterRegistry.class)` on one class (`OnClassCondition` orders first, so the bean condition never resolves a missing type) (auto-config ordered after Boot metrics) ⇒ customizer adds `TachyonMetricsListener` (timer `mcp.server.operation.duration`, tags method + snake-case outcome; starter-built server only) and `TachyonMeterBinder` feature gauges ([MetricsConfiguration](../../integrations/tachyon-spring-boot-starter/src/main/java/dev/tachyonmcp/spring/boot/TachyonAutoConfiguration.java), [TachyonMetricsListener#complete](../../integrations/tachyon-spring-boot-starter/src/main/java/dev/tachyonmcp/spring/boot/TachyonMetricsListener.java), [TachyonMeterBinder#afterSingletonsInstantiated](../../integrations/tachyon-spring-boot-starter/src/main/java/dev/tachyonmcp/spring/boot/TachyonMeterBinder.java)). Listener uses `@InternalApi` `ObservationListener` → [[api-stability]].
- Actuator conditions and backoff covered by [TachyonActuatorAutoConfigurationTest](../../integrations/tachyon-spring-boot-starter/src/test/java/dev/tachyonmcp/spring/boot/TachyonActuatorAutoConfigurationTest.java).
- Feature gauges bind directly to the available registry; Boot's metrics module is optional ([MetricsConfiguration#tachyonMeterBinder](../../integrations/tachyon-spring-boot-starter/src/main/java/dev/tachyonmcp/spring/boot/TachyonAutoConfiguration.java)). Both classpaths exercise operation timing and all three gauges ([TachyonActuatorAutoConfigurationTest#metricsWorkWithoutBootMetricsModule](../../integrations/tachyon-spring-boot-starter/src/test/java/dev/tachyonmcp/spring/boot/TachyonActuatorAutoConfigurationTest.java)). `TachyonMeterBinder` is a `SmartInitializingSingleton`, deliberately not a `MeterBinder` — Boot binds those from the optional metrics module, and binding during `MeterRegistry` creation would close a cycle back through `tachyonMetricsCustomizer`. It is declared by its own type so it can be conditioned on and replaced.
- `mcp.method.name` is tag-bounded: the dispatcher builds `OperationInfo` from the raw wire method *before* `server.getHandler(method)` resolves ([McpDispatcher#dispatchTrackedRequestAsync](../../tachyon-core/src/main/java/dev/tachyonmcp/core/server/McpDispatcher.java)), so `Rejected` with `ServerError.Kind.METHOD_NOT_FOUND` and `NotificationIgnored` are tagged `unknown` — otherwise a client mints a meter per bogus method. Keyed on the `Kind`, never the wire code: 2025_11_25 maps it to `-32601`, 2026_07_28 to HTTP `404`. Timers are cached per (method, outcome) ([TachyonMetricsListener#timer](../../integrations/tachyon-spring-boot-starter/src/main/java/dev/tachyonmcp/spring/boot/TachyonMetricsListener.java)). The collapse is deliberately narrow — any other `Rejected` kind, a `Rejected` with a null `error()` (transport-level, no JSON-RPC envelope), and every non-`Rejected` outcome keep the real method name ([TachyonActuatorAutoConfigurationTest#onlyUnservedMethodsCollapseIntoTheUnknownTag](../../integrations/tachyon-spring-boot-starter/src/test/java/dev/tachyonmcp/spring/boot/TachyonActuatorAutoConfigurationTest.java)).
- Metrics beans back off by **name**, not type: `TachyonServerCustomizer` is a plural SPI, so `@ConditionalOnMissingBean(TachyonServerCustomizer.class)` would let any application customizer silently disable MCP metrics ([TachyonActuatorAutoConfigurationTest#anUnrelatedCustomizerDoesNotDisableMetrics](../../integrations/tachyon-spring-boot-starter/src/test/java/dev/tachyonmcp/spring/boot/TachyonActuatorAutoConfigurationTest.java)).
- AOT hints come from each bean definition's **pre-instantiation** type, while `TachyonFeatureRegistrar` reads the runtime target class. They diverge for a `@Bean` method returning an interface whose implementation is built in the method body — unknowable at build time, so the native image loses those features silently. `TachyonAotProcessor#uninspectableInterfaceBeans` finds them and the processor logs a build warning; Infrastructure — `org.springframework.*` and `TachyonAutoConfiguration` with its nested configurations, nothing wider — is filtered out, or every build would warn about `tachyonServer` (itself interface-typed) ([TachyonAotProcessorTest#doesNotReportItsOwnOrSpringsInfrastructureBeans](../../integrations/tachyon-spring-boot-starter/src/test/java/dev/tachyonmcp/spring/boot/TachyonAotProcessorTest.java)). The filter is by declaring class, not by the `dev.tachyonmcp` namespace: an application configuration living there is scanned like any other ([TachyonAotProcessorTest#reportsApplicationBeansDeclaredUnderTheTachyonNamespace](../../integrations/tachyon-spring-boot-starter/src/test/java/dev/tachyonmcp/spring/boot/TachyonAotProcessorTest.java)). Hints are method categories only — the annotation layer never reads a field.
