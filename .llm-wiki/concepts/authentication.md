# 🔐 Authentication

Verdict: opt-in, per request. No provider ⇒ no handler installed, every caller `SecurityContext.anonymous()`. Provider set ⇒ every HTTP request authenticated **on its head, before aggregation**, on the handler executor (VT), within `SecurityConfig#authenticationTimeout` and with at most `SecurityConfig#maxConcurrentAuthentications` (1024) provider calls running per server (one `Semaphore` in `McpChannelInitializer`, handed to every `AuthenticationHandler`; a permit is taken before the call and given back when it returns, not when its request is answered at the timeout or its channel closes, so a stuck provider holds its permits and, at the cap, every request is answered 503; over it ⇒ 503 + `Retry-After` before the provider runs; a timeout or a capacity refusal is logged at WARN one in `AuthenticationHandler#WARN_SAMPLE`, else DEBUG); result copied into its dispatch context. No thread-local holder, session never authenticates. A 2025 session is **bound to its creator**: any other caller ⇒ `404 Unknown session`.

## 🔁 Flow

1. `McpChannelInitializer#initChannel` adds `authentication` right after `cors` (and the PRM handler before it, step 10), only when `SecurityConfig#authenticationProvider` is non-null (auth off ⇒ no handler, the pipeline is unchanged) → [[netty-pipeline]]. The caller needs no further pipeline step: the handler that processes the request takes it (step 3).
2. `AuthenticationHandler#channelRead` takes the request **head**, holds the later `HttpContent`, pauses reads through `HttpPipeliningGate#holdReads` (the gate stays the one owner of `autoRead`) only when the body is still incomplete at the end of a read or more than `AuthenticationHandler#HOLD_LIMIT` is held (`AuthenticationHandler#hold`), runs the provider on `ServerEngine#executor` and arms a deadline on the event loop (`AuthenticationHandler#begin`). It resumes on the event loop (`AuthenticationHandler#resume`); an attempt identity check makes a result after a timeout, close or removal a no-op.
3. Success ⇒ `ChannelHandlerUtils#recordCaller` publishes the caller in a channel attribute, the head and held content are replayed in order, reads resume. The handler that processes the request (`McpOperationHandler#handleRequest`; `McpInitializationHandler#handleRequest` on the branches it answers itself, and forwarded requests are taken by the operation handler) calls `ChannelHandlerUtils#takeCaller` **once, at its entry, for every method** (`getAndSet(null)`), so the next request starts with nothing, and passes the caller down explicitly (session gate `McpOperationHandler#ownedBy`, `McpDispatcher#dispatchRequestAsync` / `#dispatchNotification`, initialize, `PostSseStream` and `SseManager` for the stream expiry). With authentication on and no caller recorded (a customizer removed `authentication`) it answers 500 and processes nothing. **No connection-scoped object holds identity**: a stateful 2025-11-25 connection shares one `ChannelContext` across requests, so it has no setter and `DefaultChannelContext#securityContext` throws `IllegalStateException` rather than answer anonymous; the caller is the final field `DefaultDispatchContext#securityContext`. Anything that hands a context to user code (a custom `SessionIdGenerator`) must get the `DispatchContext` (`McpDispatcher#generateSessionId` does).
4. `McpDispatcher#dispatchContext` builds the per-request `DefaultDispatchContext(channel, server, id, caller)` from the caller passed to `McpDispatcher#dispatchRequestAsync` (or `#dispatchNotification`); `securityContext` is a final field. Handlers read `InteractionContext#securityContext`; continuations on other threads keep their request's caller. No overload defaults the caller: `McpDispatcher#dispatchRequestAsync` and `#dispatchNotification` always take a `SecurityContext`, so direct invocation and tests write `SecurityContext.anonymous()` out. `NoopInteractionContext` (programmatic dispatch) is the one context that answers anonymous.
5. **`Owner`** is the one definition of who owns state that outlives a request: `Owner#anonymous` or `Owner.Named(name)` (name = `Principal#getName()`, never blank). Always derived from a request's `SecurityContext` by `Owner#of`, never passed beside a context. Two questions, named differently on purpose: `equals` = same caller (sessions: an anonymous session serves only anonymous callers); `Owner#admits` = may this caller reach what the owner owns (tasks: anonymous admits everyone, a named owner only itself) [Owner](../../tachyon-core/src/main/java/dev/tachyonmcp/core/server/security/Owner.java). `Owner#key` / `Owner#fromKey` is the persisted form, converted at one boundary (`Session`).
6. Stateful `initialize`: `McpDispatcher#dispatchInitializeAsync` passes the request's `SecurityContext` to `ServerEngine#createSession`, which derives the `Owner` and hands its key to `SessionStore#create`. The owner is in the first persisted `SessionSnapshot#ownerKey`, final in `Session#owner`, copied by every later snapshot (`Session#snapshot`, `SessionManager#refreshed`, `InMemorySessionStore#touched`), so a restored session keeps it → [[sessions]].
7. Session binding: `McpOperationHandler#ownedBy` is the one gate for every request that names a session. The caller is taken on the event loop at the handler's entry and passed down; `Owner.of(caller)` is derived inside `ownedBy`, so nothing is read from the channel. POST lookup (request, notification, client response/error, `notifications/cancelled`) in `McpOperationHandler#parseAndDispatchPost`; GET stream and `Last-Event-ID` resume in `McpOperationHandler#handleGet` (local and restored); `McpOperationHandler#handleDelete`. `Session#isOwnedBy` is `Owner#equals`. Mismatch ⇒ empty lookup ⇒ the same `404 Unknown session` as an unknown id (`McpOperationHandler#sendUnknownSession`), WARN with a truncated id, session untouched. Stateless servers and 2026-07-28 never reach it: no session id, no GET stream, `StatelessValidatorHandler` answers first.
8. Task binding: a task-producing tool call publishes through `TaskRuntime#publish(DispatchContext, …)`, so the owner comes from the request's own context copy, safe after an async tool left the dispatch thread. `TaskEngine#publishAs` binds it; `TaskEngine#connector` is the guarded connector every caller-facing task path goes through → [[tasks]]. The binding is process-local (`TaskEngine#owners`), so a clustered or restarted server relies on a connector that authorizes from `ctx.securityContext()`; every path hands it the request's own `DispatchContext` (`TaskMethodHandlers`, `TaskEngine#awaitResult`, `TaskEngine#cancelAndAwait`, `TaskEngine#readableTaskIds`).
9. Required scopes: `ToolMethodHandlers.ToolsCallHandler#handleAsync` reads `requiredScopes` from the descriptor it just looked up **by the decoded body's tool name** (never `Mcp-Name`), and fails with `AuthenticationException#insufficientScope` unless `SecurityContext#scopes` contains all of them (exact match), before argument validation and before the tool is invoked: no handler runs, no SSE byte is written. The visibility check (`Visibility#of`) comes first, so a hidden tool is an unknown tool, never a `403`; a tool whose scopes are missing stays listed (step-up). `ChannelHandlerUtils#sendDeniedAsync` writes `403`, `Content-Length: 0`, the request's CORS headers and, for `SecurityConfig.Authentication.Bearer` only, `Bearer error="insufficient_scope", scope="<all required, declaration order>", resource_metadata="<PRM>"` (`BearerTokenAuthenticationProvider#challengeFor`). Keep-alive stays on: the request was read whole. `McpOperationHandler` and `McpInitializationHandler` (every stateless request) both call it. An undeclared tool pays a field read and `isEmpty()`.
10. Discovery: only for `SecurityConfig.Authentication.Bearer` (`McpChannelInitializer` matches on it), `mcp-endpoint` lets `ProtectedResourceMetadata#paths` through and `protected-resource-metadata` sits right after `cors`, ahead of `authentication`. It needs no token; the Origin/`Host` guard and the one CORS policy apply, so a browser's preflight to the metadata is answered by `cors` and `GET` / `HEAD` by the handler. Challenges and the served path come from `ProtectedResourceMetadata`; `NettyServerConfig` exposes `WWW-Authenticate` through CORS so a browser can read the challenge.

## 🚫 Rejections

| Case | Response | Proof |
|---|---|---|
| no `Authorization`, or non-Bearer scheme | 401 `WWW-Authenticate: Bearer resource_metadata="<PRM url>"[, scope="<scopes>"]` | `BearerTokenAuthenticationProvider#authenticate` |
| several `Authorization` headers, `access_token` query param | 400 `Bearer error="invalid_request"` (no discovery parameters: a malformed request, which finding the authorization server does not fix) | `AuthenticationException#bearerInvalidRequest`, `BearerTokenAuthenticationProvider#authenticate` |
| token not `b64token`, verifier rejects with a 401 | 401 `Bearer error="invalid_token", resource_metadata="…"[, scope="…"]`; the verifier's own challenge is replaced | `BearerTokenAuthenticationProvider#B64TOKEN`, `BearerTokenAuthenticationProvider#authenticate` |
| verified token with the wrong, or no, audience; verified token already expired | 401 `Bearer error="invalid_token", resource_metadata="…"[, scope="…"]`, the handler never runs | `BearerTokenAuthenticationProvider#authenticate` |
| `GET` / `HEAD` on a PRM path | 200 JSON, no token; `HEAD` has the `GET` headers (`Content-Length` included) and no body | `ProtectedResourceMetadataHandler#channelRead` |
| CORS preflight (`OPTIONS` + `Origin` + `Access-Control-Request-Method`) to a PRM path | answered by `cors` with the existing policy (a foreign origin: 403 from `dns-rebinding`) | `TachyonCorsHandler`, `EndpointValidatorHandler#channelRead` |
| other method on a PRM path | 405 + `Allow: GET, HEAD`, connection closes | `ProtectedResourceMetadataHandler#channelRead` |
| custom provider throws `unauthorized(msg, challenge)` | 401 with that challenge, never Bearer; `badRequest` is 400 with or without one. `AuthenticationHandler` writes `AuthenticationException#wwwAuthenticate` and holds no scheme | `AuthenticationHandler#reject` |
| a challenge parameter that cannot be sent (line break, control or non-ASCII character) | `IllegalArgumentException` at `AuthenticationChallenge#withParam` ⇒ provider failure ⇒ 500, no header injected | `AuthenticationChallenge#requireQuotable` |
| provider throws `unavailable(msg, retryAfter)` | 503, `Retry-After`, no challenge, DEBUG (the message at TRACE only) | `AuthenticationException#unavailable`, `AuthenticationHandler#reject` |
| provider throws anything else, or returns a principal without a name | 500, no challenge; WARN names the exception class only, the message and causes (a token can be in them) are at TRACE | `AuthenticationHandler#reject`, `AuthenticationHandler#authenticate` |
| the verifier reports no issuer on a server with several authorization servers | provider failure ⇒ 500: `issuer\|name` could collide | `BearerTokenAuthenticationProvider#ownerKey` |
| provider still silent at `authenticationTimeout` (default 10 s) | 503 + `Retry-After` (timeout in seconds, at least 1), no challenge, WARN, connection closes; the provider is not interrupted and its late result is ignored | `AuthenticationHandler#expire` |
| a request of any method reaches the handler that processes it with no recorded caller, on a server that authenticates | 500, WARN, nothing processed (fail closed) | `ChannelHandlerUtils#takeCaller`, `McpOperationHandler#handleRequest`, `McpInitializationHandler#handleRequest` |
| `tools/call` of a tool whose `requiredScopes` the caller does not all hold | 403, empty body; `Bearer` ⇒ `WWW-Authenticate: Bearer error="insufficient_scope", scope="…", resource_metadata="…"`; `Custom` ⇒ no challenge; never JSON-RPC; the tool never runs; session unaffected | `ToolMethodHandlers.ToolsCallHandler#handleAsync`, `ChannelHandlerUtils#sendDeniedAsync` |
| a feature the access policy hides from the caller | listed nowhere; any request naming it answers exactly like an unknown one (same code, message, data); a hidden URI is subscribed / acknowledged like an unknown one and never delivered | `Visibility#of`, `DefaultResourceRegistry#isHidden` |
| `AuthenticationException` thrown by a policy or a handler | its status: `401` (bearer: the server's `invalid_token` challenge), `403`, `400` or `503` + `Retry-After`, empty body (`ChannelHandlerUtils#sendDeniedAsync`); after the stream started, a JSON-RPC `-32600` `Unauthorized` / `Forbidden` / `Service unavailable` as its last event | `SecurityRejection#of`, `McpDispatcher#denied`, `HandlerFutures#invokeAndMap` |
| access policy throws anything else | `-32603` internal error, nothing served | `McpDispatcher#handleHandlerError` |
| 2025 session id used by another caller (POST, GET, `Last-Event-ID`, DELETE) | 404 `Unknown session`, session survives | `McpOperationHandler#ownedBy` |
| task owned by another caller: `tasks/get`, `result`, `cancel`, `update` | `-32602` `Task not found`, identical to an unknown id; the real connector never runs; `tasks/list` omits it | `TaskEngine#connector` |
| a publish that would change a task's owner | tool path: generic `-32603 Internal error`; WARN with a truncated id; nothing about the task changes | `TaskEngine#publishAs` |

Empty body, request CORS decision applied, keep-alive off. Logs carry the path only (`AuthenticationHandler#path`): the query may hold a token. The Netty wire log is the one place that could hold a token: TRACE hex-dumps every byte, `Authorization` included, so it stays off in production; DEBUG logs sizes only `McpChannelInitializer#wireLogger`.

Runs on the head after Origin, endpoint and CORS, ahead of version/Accept/Content-Type/body-size checks ⇒ a refused caller gets 401 whatever else is wrong, costs its headers only (no body buffered, no `100 Continue`, connection closed). ⚠️ A client that streams its body without `Expect` may see a reset instead of the 401, since the unread body is still in the socket when the connection closes. `readerIdleTimeout` below `authenticationTimeout` lets an idle close fire mid-authentication.
